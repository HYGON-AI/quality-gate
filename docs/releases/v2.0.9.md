# v2.0.9 — Bounded long-addition analysis

## Fix

The sensitive runtime-output analyzer previously rejected any addition tree
deeper than 20 nodes, including ordinary file-list concatenations in lightop
PR #114. Its `setup.py` has 35 additions; an older build script has 27. These
are syntactically valid build expressions, not evidence of a sensitive output.

Evaluate and traverse addition trees iteratively, retaining grouping, typed
candidate values, left-to-right inference and source-line origins. Unknown
values keep the existing short circuit, while nested visible calls remain
inspected. Long string concatenations still produce sensitive-word findings.

## Limits and compatibility

Work/time, candidate-count and string-size limits remain active, as does the
depth limit for nested non-addition expressions. Exceeded limits remain an
Invalid Scan. Workflow memory/time restrictions and Docker settings are unchanged.
No scanner images, admission policies, public check names or caller permissions
change. Historical v2.0.8 release tags remain fixed.

## Validation and rollout

Run portable self-tests/unit tests and Linux Python 3.9/3.11/3.12 CI. Replay the
actual lightop base/head through the candidate engine on Python 3.12.13 without
executing target code. Cover long call/list/string chains, grouping, incremental
origins, nested output calls and retained resource limits; rerun the historical
branch-deduplication and scanner reliability regressions.

Require independent PR approval and passing validation before release. Publish
v2.0.9 and then promote stable to the reviewed commit. Existing @stable callers
need no workflow edits. A caller selecting @v2.0.9 directly needs that exact
workflow ref allowed in its runner group before switching.
